## 1. Project Overview & Goals {#project-overview--goals}
- **Goal:** Build a portfolio of HTML5/JavaScript games that can be played instantly in a browser (no download, no app‑store fees).  
- **Target Audience:** Casual players discovering the games through a YouTube dev‑vlog series.  
- **Success Metrics:**
  1. *Technical:* Zero‑runtime errors, smooth 60 fps on desktop browsers, < 100 KB JS bundle for the first game.  
  2. *Community:* At least 500 unique visitors per game within the first month, positive comments on the vlog.  
  3. *Process:* All source lives in a public GitHub repo, each commit is tagged with a clear “Feature / Fix” message.
- **Constraints:** $0 cost – use only free tiers (GitHub, Vercel/Netlify, Gemini CLI free quota, OBS Studio for video).  
- **Technology Stack (as per action plan):**
  - **HTML5 Canvas** for rendering (fallback to CSS for UI).  
  - **Phaser 3** (or vanilla Canvas for simple prototypes).  
  - **Matter.js** for physics (used later for Rock‑Stacking demo, not needed for TD).  
  - **EasyStar.js** (A* path‑finding) for tower‑defense enemy navigation.  
  - **GitHub Pages / Vercel** for static hosting.  
  - **OBS Studio + CapCut** for vlog capture.

## 4. Phase 2 – Tower‑Defense MVP (Game 1) {#phase2---tower‑defense-mvp-game1}
### 4.1 Core Architecture (as per research)
1. **Modular ES6 files** – `GameScene.js`, `TowerManager.js`, `EnemyManager.js`, `WaveManager.js`, `GridSystem.js`.
2. **Event‑Driven Communication** – use `Phaser.Events.EventEmitter` (or a tiny custom emitter) to decouple tower placement from enemy path updates.
3. **Configuration‑Driven Data** – store towers, enemies, and wave definitions in JSON (`towers.json`, `enemies.json`, `waves.json`).
4. **Path‑Finding** – integrate **EasyStar.js** (A*) for dynamic rerouting when a tower blocks a path.

### 4.2 Detailed Tasks
| # | Task | Sub‑tasks / Code Snippet | Acceptance Criteria |
|---|------|--------------------------|---------------------|
| **2.1** | **Add Phaser 3** (via CDN) to `index.html` | ```html
<script src="https://cdn.jsdelivr.net/npm/phaser@3/dist/phaser.min.js"></script>
``` | Phaser loads without console errors. |
| **2.2** | **Create Game Scene** (`games/td/TDScene.js`) | - Extend `Phaser.Scene`  <br>- Load tilemap JSON (see step 2.3)  <br>- Set up camera and UI overlay. |
| **2.3** | **Design Tilemap with Tiled** | - Download **Tiled** editor (free).  <br>- Create a 20×15 grid, define `ground`, `path`, `buildable` tiles.  <br>- Export as `map.json` into `assets/td/`. |
| **2.4** | **Load Map in Scene** | ```js
this.map = this.make.tilemap({ key: 'tdMap' });
const tiles = this.map.addTilesetImage('tileset', 'tiles');
this.groundLayer = this.map.createLayer('Ground', tiles);
this.pathLayer   = this.map.createLayer('Path', tiles);
``` |
| **2.5** | **Implement Grid System** (`GridSystem.js`) | - Parse the tilemap to a **2‑D array** (`0 = walkable, 1 = blocked`).  <br>- Expose `isWalkable(x, y)` and `toggleBlock(x, y)`. |
| **2.6** | **Integrate EasyStar.js** (`Pathfinder.js`) | ```js
this.easystar = new EasyStar.js();
this.easystar.setGrid(gridArray);
this.easystar.setAcceptableTiles([0]); // walkable only
this.easystar.enableDiagonals();
``` |
| **2.7** | **Tower Placement UI** | - Add a sidebar with tower icons (CSS + click listeners).  <br>- On click, check `grid.isWalkable(tx, ty)`.  <br>- If valid, **place tower sprite**, mark tile as blocked, **re‑calculate path** via EasyStar. |
| **2.8** | **Enemy Wave Manager** | - Load `waves.json` (each wave defines enemy type, count, spawn interval).  <br>- Spawn enemies at the map start tile, assign them the current path from EasyStar. |
| **2.9** | **Enemy Path‑Following** | - In each enemy’s `update()` call, ask EasyStar for the next waypoint.  - Move using `Phaser.Math.Linear` for smooth interpolation. |
| **2.10** | **Tower Attack Logic** | - Each tower has range, fire‑rate, damage.  - Use Phaser’s `time.addEvent` to periodically check for enemies within range and fire projectiles. |
| **2.11** | **HUD Elements** | - Gold counter, lives remaining, wave indicator.  - Use **bitmap fonts** for crisp retro feel. |
| **2.12** | **Game‑Over & Victory** | - When lives hit 0 → display “Game Over” overlay.  - When all waves cleared → display “Victory” overlay with a “Play Again” button. |
| **2.13** | **Responsive Design** | - Ensure canvas scales to the browser window while preserving aspect ratio (`SET_DISPLAY_SIZE`). |
| **2.14** | **Testing & Debugging** | - Play through 3 full waves.  - Verify that placing a tower on the path **re‑calculates** enemy routes correctly.  - Check for memory leaks (no new objects in the update loop). |
| **2.15** | **Commit & Tag** | ```bash
git add games/td/
git commit -m "feat: tower‑defense MVP – grid, pathfinding, tower placement, basic HUD"
git tag -a v0.1‑td -m "First playable tower defense"
``` |

### 4.3 Benchmark Features to Mirror (from Appendix)
- **Multiple Tower Types** – Bloons TD: basic, sniper, splash.  Implement at least two towers now; add more later.
- **Upgrade Paths** – Allow each tower to be upgraded twice (damage ↑, range ↑).  Use a simple click‑to‑upgrade UI.
- **Enemy Variety** – Fast, armored, and “boss” enemies.  Store stats in `enemies.json`.
- **Wave Progression Curve** – Increase enemy health and count by ≈ 20 % each wave (mirrors Kingdom Rush pacing).
- **Audio Cues** – Play a short “ding” when a tower is placed, and a “boom” on enemy death (helps perceived polish).
